# v2v-tma — Telegram Mini App для голосового та текстового AI-консьєржа

Фронтенд для рушія [v2v-demo](https://github.com/valpere/v2v-demo): голос і текст,
**Voice-to-UI** (картки підсвічуються, кошик наповнюється під час розмови) та
оплата в **Telegram Stars (XTR)**. Статус — **живий прототип, не MVP**.

- Текстовий режим за замовчуванням і без витрат; озвучення — безкоштовний Web Speech API у браузері. Хмарний голос — лише за явною дією користувача.
- 4 домени: піцерія «Папа Пепе», барбершоп «Барбароса», автосервіс «Подбай-Авто», магазин «Lyapko Shop».
- Кошик і ціни рахує **сервер**: клієнт надсилає лише `item_id` і кількість; `initData` Telegram перевіряється (HMAC-SHA256, до 24 год).

## Як це влаштовано

```
Telegram-бот ─┐
цей TMA       ─┼─►  /v1 API рушія (v2v-demo)  ─►  LLM / STT / TTS
чистий веб    ─┘
```

Поки рушій не віддає `/v1`, `cmd/server` відповідає на нього **заглушкою** (детермінований пошук за ключовими словами, без LLM). З `ENGINE_URL` той самий сервер проксіює `/v1` до справжнього рушія. Контракт: [`docs/API.md`](docs/API.md). Що готове, а що заглушка, і що робити далі: [`docs/HANDOFF.md`](docs/HANDOFF.md).

## Запуск

```bash
make run                      # DEV_AUTH=1, http://localhost:8085
make check                    # gofmt, vet, тести з -race, node --check, збірка
```

| Змінна | Призначення |
|---|---|
| `TELEGRAM_BOT_TOKEN` | перевірка `initData` і створення Stars-інвойсів; без нього сервер стартує лише з `DEV_AUTH=1` (інвойси фальшиві) |
| `DEV_AUTH=1` | лише локальна розробка: запити без `Authorization` приймаються |
| `ENGINE_URL` | проксі `/v1/*` до рушія замість заглушки |
| `PORT` (8085), `WEB_DIR` (`web`) | |

Telegram відкриває Mini App лише по **HTTPS** — для перевірки всередині Telegram потрібні домен/тунель (див. HANDOFF §3).
