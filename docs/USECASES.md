# v2v-tma — Use Cases

> **Статус (2026-10-14):** UC-01, 02, 03, 05 працюють у прототипі (з заглушкою замість LLM); UC-04 — лише через браузерний Web Speech; UC-06 — створення інвойсу є, підтвердження оплати належить рушію; UC-07 — після підключення рушія v2v-demo (grounding gate). Контракт — [`API.md`](API.md).

Документ описує сценарії використання інтерактивного Telegram Mini App голосового та текстового AI-консьєржа з підтримкою мультидоменного каталогу та оплати через Telegram Stars.

---

## 1. Актори

1. **Клієнт / Покупець (User):**
   - Користувач Telegram, який відкриває Mini App з мобільного пристрою (iOS / Android) або десктопу.
   - Спілкується з асистентом текстом або голосом (on-demand).
   - Переглядає товари/послуги, додає позиції в кошик, змінює параметри та оплачує замовлення.

2. **AI-консьєрж (Assistant):**
   - Інтелектуальний агент, заземлений на конкретний бізнес-домен (базу знань та каталог послуг).
   - Розпізнає наміри (intents), виділяє сутності (entities) та генерує структуровані мутації для інтерфейсу.
   - Відповідає текстом та (у голосовому режимі) синтезованим голосом.

3. **Telegram Platform:**
   - Провайдер ідентифікації через `initData` (HMAC-SHA256).
   - Провайдер нативних UI-елементів (MainButton, BackButton, HapticFeedback, ThemeParams).
   - Провайдер платежів за цифрові товари та послуги (Telegram Stars).

4. **Власник бізнесу / Адміністратор:**
   - Отримує структуровані замовлення та ліди з деталізацією (позиції, контакти, обраний час, статус оплати).

## 3. Детальний опис сценаріїв

### UC-01: Ініціалізація та безпечна автентифікація
- **Основний потік:**
  1. Користувач запускає бота `@v2v_tma_bot` та тисне кнопку «Відкрити консьєржа».
  2. Telegram відкриває WebApp, передаючи криптографічний рядок `Telegram.WebApp.initData`.
  3. Клієнтський застосунок адаптує кольорову гаму до темної/світлої теми Telegram (`themeParams`).
  4. Клієнт надсилає `initData` на бекенд для верифікації.
  5. Бекенд валідує HMAC-SHA256 хеш за допомогою `bot_token`. При успіху повертає сесію та стан користувача.
- **Альтернативний потік:**
  - Якщо `initData` невалідний або відсутній (запуск у звичайному браузері без Telegram), сервер відповідає `401`. Режим без Telegram доступний лише локально з `DEV_AUTH=1` (інвойси фальшиві); гостьовий веб-режим — завдання рушія (анонімний токен з лімітами).

---

### UC-02: Вибір бізнес-домену
- **Основний потік:**
  1. На головному екрані або у верхній панелі користувач бачить компактний перемикач доменів:
     - 🍕 **Піцерія «Папа Пепе»** (каталог страв, модифікатори, доставка).
     - 💈 **Барбершоп «Барбароса»** (послуги, вибір майстра, бронювання слотів).
     - 🚗 **Автосервіс «Подбай-Авто»** (діагностика, ТО, оцінка вартості робіт).
     - 🛍️ **Магазин «Lyapko Shop»** (аплікатори, фільтрація за призначенням).
  2. При виборі домену миттєво перезавантажується активна база знань (KB) та каталог товарів/послуг.
  3. Кошик і діалогова історія ізолюються в межах обраного домену.

---

### UC-03: Текстова взаємодія (Основний режим за замовчуванням / Zero-Cost)
- **Основний потік:**
  1. Користувач вводить текстовий запит у поле вводу (або обирає швидку кнопку-підказку, наприклад: *«Порадь гостру піцу з сиром»*).
  2. Запит надсилається на бекенд разом з ідентифікатором активного домену.
  3. LLM (з заземленням на KB обраного домену) формує структуровану відповідь:
     - Текстове пояснення для користувача.
     - Список команд для мутації інтерфейсу (`UI_ACTIONS`: підсвітити товар, додати в кошик, відкрити модалку).
  4. Клієнтський Mini App відображає репліку асистента та **наживо оновлює UI** (картка товару підсвічується, додається бейдж).
  5. **Витрати на TTS дорівнюють нулю**, оскільки аудіосинтез вимкнений.

---

### UC-04: Голосова взаємодія On-Demand (Voice-to-UI)
- **Основний потік:**
  1. Користувач перемикає тумблер у режим `🎤 Голос` або затискає кнопку Push-to-Talk.
  2. Застосунок активує візуалізатор аудіохвилі (Web Audio API) та записує голосовий фрагмент (WebM/Opus).
  3. Аудіо передається на бекенд, де STT (або браузерний Web Speech API на клієнті) розпізнає мову (UK/EN).
  4. Бекенд обробляє запит через LLM + KB і повертає:
     - Текстову репліку та UI-мутації.
     - Синтезований аудіопотік (TTS) або вказівку клієнту відтворити мову через нативний SpeechSynthesis.
  5. Екран оновлює товари, а з динаміка звучить відповідь асистента.

---

### UC-05: Керування кошиком та параметрами замовлення
- **Основний потік:**
  1. Товари можуть додаватися двома способами:
     - **Голосом/текстом:** *«Додай 2 Пепероні та 1 колу»* → асистент сам наповнює кошик потрібними артикулами.
     - **Тапом по UI:** звичайне натискання на кнопку `+` у картці товару.
  2. У нижній частині екрана відображається плаваючий віджет кошика з сумою та кількістю.
  3. Натискання на кошик відкриває екран перевірки замовлення, де можна змінити кількість або видалити позицію.

---

### UC-06: Оформлення замовлення та оплата через Telegram Stars
- **Основний потік:**
  1. Користувач переходить до оформлення замовлення.
  2. Telegram `MainButton` активується із текстом: `Оплатити 50 ⭐ (Telegram Stars)`.
  3. При натисканні викликається бекенд для створення інвойсу через Telegram Payments API (`createInvoiceLink`).
  4. Клієнт відкриває нативну платіжну шторку Telegram: `Telegram.WebApp.openInvoice(url)`.
  5. Після успішної оплати:
     - Спрацьовує нативний Haptic Feedback (`notificationOccurred('success')`).
     - Замовлення позначається як сплачене.
     - Власник бізнесу та бот отримують підтверджений чек у чаті.

---

### UC-07: Захист від галюцинацій та ескалація (Guardrails)
- **Основний потік:**
  1. Користувач запитує нерелевантну інформацію (наприклад: *«Який курс біткоїна?»* або питання про конкурентів).
  2. Шлюз заземлення (Grounding Gate) визначає низький рівень перекриття з базою знань (KB Overlap < поріг).
  3. Асистент ввічливо інформує про спеціалізацію: *«Я можу допомогти лише із замовленням у нашому закладі. Бажаєте зв'язатися з адміністратором?»*.
  4. Жодних вигаданих фактів, цін чи обіцянок.
